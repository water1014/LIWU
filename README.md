# LIWU · 小手机（框架版）

仿手机交互的单文件前端框架，用 Vue 3 编写，所有数据存在浏览器 IndexedDB。
定位是「界面像小手机，用起来像 Operit / RikkaHub / Kelive 那类角色扮演客户端」。

## 文件

| 文件 | 说明 |
| --- | --- |
| `liwu.html` | **成品**，双击即用，485 KB，Vue 运行时已内联，断网可跑 |
| `liwu-src/` | 源码，按层拆成 css / js 分片，改完跑 `python3 build.py` 重新打包 |
| `liwu-src/build.py` | 打包脚本，把 `src/*` + `vue.js` 拼成单文件 |

手机上打开需要支持 IndexedDB 的浏览器；桌面端会显示一台居中的手机外框，窄屏下自动铺满全屏。

## 数据

`LIWU_DB` 共 9 张表，全部走 `DB` 一个网关，没有散落在各处的 localStorage：

`accounts` · `characters` · `chats` · `messages` · `worldbooks` · `memories` · `settings` · `files` · `meta`

- 图片一律转 Blob 存 `files`，用时换成 objectURL，替换时旧文件自动删除（不残留）
- 设置按账号分 key：`cfg_<accountId>`，多账号数据天然隔离
- 「设置 → 应用数据」有总占用、分项占用、变量清单、单表清理与全清

## 还留在半路的部分

1. **没有 API 时走本地模拟回复**（`A.mockReply`），界面能完整跑通；配好 API 后自动切真实调用。目前整段返回，没有做流式。
2. 聊天回复在切换页面后仍会写库，但「后台继续回复」没有做通知与并发队列。
3. 发现页的「论坛」只有入口和提示，页面未做。
4. 朋友圈的点赞 / 评论 / 转发是本地状态，评论未接 AI。
5. 记忆的 AI 合并目前是规则式摘要，等真实模型接入后要换成结构化输出。
6. 音乐只是界面里的播放状态，没有音频文件，也没有接外部音源。
7. 桌面组件只做同尺寸交换，没有像素级自由拖拽。
8. 检索工具（`<tool>`）能渲染成注释并可展开，但「下钻原始记忆」需要模型按格式输出，尚未在提示词里强制。

## 怎么继续改

```bash
cd liwu-src
python3 build.py       # 产物 liwu.html 在同目录
```

- 换配色只改 `01-tokens.css` 顶部变量
- 加一个应用：`12-store.js` 的 `APPS` 里加一条 → `40-main.js` 的 `VIEWS` 里注册页面组件 → 需要的话在 `31-archive-store.js` 的商店里加卡片
- 接真实模型：`12-store.js` 的 `A.callAPI`，三种协议都已写好请求体，只差把 `fetch` 换成流式读取
